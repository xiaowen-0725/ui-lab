- 从 shadcn-admin 或 shadcn-studio 相关项目选取实际复用基线；具体项目、版本、可复用范围还需在查证组件底座与许可后确定。

## 目录与交付草案

维持“组件 → 区块 → 页面 → 外壳/整站”的真实引用方向，以便后续营销和个人网站复用；不为未来场景预建没有实际用途的通用框架。拟议定位如下，最终路径和公开身份随新规格确认：

| 职责 | 拟议定位 | 边界 |
| --- | --- | --- |
| 官方基础控件 | components/ui/ | Base UI 版 shadcn/ui；保留上游 API/来源，不替换其他现有资产的自写控件 |
| 后台组合区块 | 与后台页面共置的 blocks/helpers | 复用上游卡片、表格、图表等组合；有实际共享职责再抽取 |
| 独立页面 | components/pages/ 下的后台模块 | 页面独立消费，数据/文案/动作接口与适配差异需先列清 |
| 共用外壳与整站 | components/site-shells/ | 整站引用真实页面与壳，不复制另一份预览实现 |
| 站点及消费者适配 | components/app/sites/、app/[locale]/sites/ | Next、国际化、路由、偏好存储和演示请求留在包装层 |
| 登记及分发 | lib/pages.ts、lib/sites.ts、lib/registry.ts | 已删除旧模板身份；其他既有身份保持，新增资产按真实源码闭包安装 |

此前已确认的独立页面/外壳/整站消费、无业务密钥运行示例、Next/Vite 支持、中英双语与主题状态保留方向继续作为输入；本次不重复请求授权，也不把历史验证当作新实现通过。新源码是否满足这些边界需重新验证；若上游移植需要改动源码/API，先提供具体方案。
