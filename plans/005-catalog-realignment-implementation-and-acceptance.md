日期：2026-10-03。状态：阶段0–5工程验收通过；阶段6未发布。最终结果见验收报告及台账。

用户要求按七个目录入口调整全部现有内容，修复红队发现，并由统筹负责实施准入、验收准入及问题闭环。本文是执行计划，不是 current implementation，也不是视觉批准记录。

## 1. 目标与完成定义

保留词典、组件、区块、页面、整站、主题、灵感七入口及右侧文档；整理原有资产，使人能浏览同一份真实资产，AI 能准确发现、选择安装目标、装配并验证。前端维护阶段保留既有契约基准，能识别上游变化。

完成必须同时满足：

1. 现有内容全部有明确归属、唯一实现来源、能力说明和迁移结果，不能只改顶栏。
2. 八项红队问题都有修复或风险消除的证据；未验证、延期和仅写文档均不能算修复通过。
3. 所有发布的安装地址、变体、依赖和 Recipe 引用有效；站点、Catalog、CLI、Skill 的事实一致。
4. 交付真实完整页面和多页组合实例，消费者能使用实际分发源码运行，不能根据截图重新生成。
5. 工程门禁、消费者运行、交互与视觉检查分别记录；机器检查不冒充用户视觉批准。
6. 旧入口与安装契约的兼容情况明确，无未解释的数据丢失或无效引用。

前端生命周期在本计划中指发现命名 → 查询已有资产 → 安装 → 页面/多页装配 → 接入消费者 → 验证 → 升级维护。消费者业务、后端、鉴权、数据库和发布运维不因本次整理自动纳入；UI Lab 自身发版与线上核验单独作为发布关卡。不恢复 Studio、Order 或批准生命周期。

## 3. 目标目录及旧内容处理

```text
词典
  概念：操作 / 填写 / 选择 / 导航 / 黑话 / 浮层 / 反馈 / 内容
  动效：出现 / 反馈 / 文字 / 滚动 / 循环 / 切换 / 缓动弹簧 / 图标
组件
  单一界面职责；用途和动效作为检索维度；显式展示变体安装目标
区块
  已组织的界面布局 / 页面区段及其结构变体
页面
  完整页面 / 布局骨架（明确区分交付能力）
整站
  多页组合 / 共享外壳（明确区分交付能力）
主题
  风格 / 配色 / 工作台皮肤 / 视觉取值 / 可运行 Theme Kit
灵感
  来源 / 网站 / 品牌
文档
  查询安装 / 主题系统 / 装配 / 验证维护
```

### 分类执行规则

- 组件按职责分，不按体积、文件数或原目录位置分。`components/agents` 中的单职责原语重新归入组件；已有布局组合归入区块。内部 helper 不升成目录资产。
- 现有 `motion`/`blocks` 分类同时承担 URL 与分发兼容职责。先拆清领域归属与历史分类的关系，新增最少的明确元数据或映射，再逐项迁移，不能用一次数组搬迁同时破坏路径、预览和安装。
- 例如 `otp-input`、`voice-orb`、`suggestion`、`code-block`、`inline-citation` 进入组件职责复核；`login-card`、`billing-plan-grid`、页面 sections 进入布局组合复核；`not-found` 的整屏变体进入页面能力复核；`agent-workbench` 作为共享外壳被整站引用，不直接标成完整整站。最终以源码和公开接口为依据。
- 每项区分可预览、可复制 token/prompt、可安装、可组合及支持的 Profile。能力必须能验证，不能靠 badge 声明完成。
- “模板”是用户检索语言，映射到具体页面、整站或组合契约；不另建重复保存同一源码的含混层。
- `styles`、`palettes`、非 motion 的 atoms 进入主题；缓动、弹簧、时长及滚动解释进入动效词典的发现关系，继续复用 `lib/ease.ts` 等既有值。
- 灵感纳入可机器发现的参考信息时保留 external-only/provenance/许可等边界；不提供虚构安装命令，不把外部品牌资产变成主题交付。

| 职责 | 现有/规划位置 | 处理 |

## 7. 验收准入与执行

提交验收前：实现者提供变更文件、任务/R-ID、台账更新、相关检查结果、已知限制、消费者复现步骤及回滚说明。相关失败测试必须实际复测通过。不可用编译成功代替安装、用静态a11y扫描代替键盘交互、用Audit成功代替视觉检查。

### 工程与协议

- 根仓 `bun run check`；按影响范围运行现有 tests 与新增跨层/负向测试。
- CLI 源码变化执行 `bun run --cwd cli typecheck` 与 `bun run --cwd cli build`，并实际检查构建产物帮助/JSON/失败退出码。
- Catalog/Recipe/词汇变化执行 `bun run cli:snapshot`，记录 URL base 与快照来源，比较冻结数据和现行真源。
- 根仓生产构建在 dev 停止并确认安全后执行；不得与共用 `.next` 的 dev 同时运行。共享环境的服务由统筹协调，避免无故中断用户工作。
- 安装URL检查覆盖所有可安装项与变体；locale路由、旧深链、机器端点排除、本地化和sitemap按迁移范围核验。

### 消费项目

- `next-app` 与 `vite-app` 使用独立、干净的实际 React package；monorepo统一 `--dir`；拒绝 workspace root 的假成功。
- 对安装映射修复执行真实 shadcn 安装及消费typecheck/build；安装声明支持多个Profile的代表原语与核心组合。
- `electron-renderer` 若继续声明支持，必须在实际renderer包验证；只有Vite夹具不能叫Electron运行验收。Profile-specific路由/SSR/font行为在对应Profile检查。
- Workbench变化执行 `bun run benchmark:greenfield`；首次先在fixture `bun install --frozen-lockfile`。其结果只覆盖既有Graphite/Workbench回归。
- 负向验证覆盖缺文件、错误引用、来源失败、Lock变化、主题覆盖；仅新建空项目的正向成功不够。

### 体验与内容

- 中英、明暗、桌面/平板/手机、长中文、loading/empty/error/success、键盘与触屏、reduced-motion逐项记录。
- 检查目录检索与选择：一个名字指向明确资产，变体可识别，不可安装参考不会给虚构命令。
- 页面和多页实例使用相同分发源码；不靠站点mock、私有provider或硬编码的演示数据运行。
- 自动扫描、浏览器运行与人工视觉评审分别记录。用户未作视觉选择时，只标工程/交互结果，不制造用户批准。

验收失败退回原任务，修复后复测失败场景及受影响回归。所有当前发布范围内的P1和P2修复项未关闭时，本项目整体工程验收不得标通过；明确排除范围的能力不能对外宣称覆盖。
