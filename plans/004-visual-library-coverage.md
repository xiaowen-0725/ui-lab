# 可视前端设计库：完整覆盖地图

日期：2026-09-12。状态：根据用户对原型覆盖不足的反馈补充的范围与信息架构方案。没有把未实现条目记录为当前能力。

## 本轮纠偏

用户认可了视觉浏览，但指出八个样本未覆盖主流前端设计与常见页面部位。这个反馈成立：上一轮验证了局部操作流程，不能替代整体内容原型。接下来优先呈现完整目录和页面部位关系，再按使用需要补齐各条目的调节和交付。

产品范围仍是整个前端设计领域。完整原型必须让人看见广度，而不能只在方案文字中说会覆盖。

## 用户应如何找到这些内容

保留“探索设计单元 / 风格与体系 / 灵感参考”的主任务入口。探索内部提供相互关联的浏览视角，而不是把所有专业分类挤成导航标签。

1. **按页面部位找**：看到页面骨架，点击顶部、中段、底部或侧栏；对应区域展示若干真实缩略样本，再进入结构变体。适合“我想改这里，但不知道它叫什么”。
2. **按组件用途找**：导航、输入、展示、反馈。适合“我需要一个筛选区域”“这里要显示很多数据”。
3. **按设计要素找**：文字、颜色、布局、形态、材质、图形、动效。适合“这个区域太挤”“想让边界更柔和”。

同一个条目可从不同视角进入，但继续使用同一份数据与源码引用，避免重复建库。

长页面的可视结构示意：

```text
页面顶部      通知 / 导航 / 首屏
                 ↓
建立理解      客户标墙 / 产品演示 / 核心卖点
                 ↓
展开内容      图文区 / 功能组 / 步骤 / 数据
                 ↓
建立信任      案例 / 评价 / 团队
                 ↓
支持决定      定价 / 常见问题
                 ↓
页面底部      行动区 / 联系或订阅 / 页脚
```

这个顺序用于识别常见部位，不是强制每个页面都具备所有区块。产品还要呈现空间布局与局部组件，覆盖内容站、工具、后台、营销站等用途。

## 下一轮整体原型的完成标准

- 浏览层呈现上述完整领域，接入可复用的现有页面布局、区块、组件、基础词汇、风格和主题；无需所有条目同时实现完整参数编辑。
- 常见部位必须有可见结构或真实预览，不能用一串名词或统计数字代替内容体验。
- 先按用途给少量代表样本，再展开变体、分类和搜索；内容增长不等于首页同时播放上百个预览。
- 条目按实情区分“可预览”“可调节”“可安装/导出”。库存未接入的项目也明确标记，不能用不可操作占位图伪装完成。
- 首批精调与输出继续保留，成为可复用详情方式；复杂组件可以有专用参数和状态，而非强行共用两个滑块。
- 现有 AI 专用条目保留在相应场景，但普通前端部位和基础设计应获得足够代表性，避免总库存掩盖覆盖不均衡。
- 对照与输出必须在实际内容、尺寸和状态下检查；“任意拼装即可达到 80 分”仍是待验证目标，不能当作能力承诺。

## 实施取舍

下一阶段优先级应从“继续打磨四个样本”切换到“完整内容组织与真实资产接入”。先完成覆盖矩阵和入口原型，再补高频缺口。现有 Next.js/React、领域数据真源和 registry 可以继续使用；本轮未发现需要整体换栈的依据。

当前操作原型及其实现保存在 `codex/visual-library-experience` 分支。本文补充完整范围，不意味着该分支已经实现了这张地图。
