## 已确认的首版支持范围

| 消费环境 | 首版要求 | 声明边界 |
| --- | --- | --- |
| Next App Router | 新资产真实安装、strict typecheck、生产 build/start、SSR/hydration、深链与完整本地流程 | 框架导航和主题首帧在消费者包装；安装源码不 import Next/next-intl |
| Vite React | 新资产真实安装、strict typecheck、生产 build/preview、客户端导航与完整本地流程 | 使用消费工程的路由包装；不要求所有消费者选同一个 Router |
| Electron renderer | 保持纯 React/无服务端依赖的可适配方向，后续再补新模板运行验收 | 首版新资产不先登记为已支持；现有资产的 Electron 身份与实际支持范围保持兼容 |

推荐首版正式支持 next-app 与 vite-app，避免把未验收的 Profile 写入新模板或新页面的 profiles。技术基线沿用 React 19、TypeScript、Tailwind CSS 4；涉及 Motion 时沿用现有 token/hydration/reduce 契约。精确最低/解析版本在实施证据中记录；新图表依赖按真实图声明并核对 React/react-is 兼容，不用缓存中一个较高版本的通过结果证明最低版本。

首版共九类界面：总览、项目列表、项目详情、成员、账单、设置、登录、注册、找回密码。设置扩展同一 WorkbenchSettingsPage；其他新增职责与名字以复用决定和实际登记为准。示例全部使用本地样本与模拟结果，启动不需要鉴权、数据库、支付或邮件密钥。

## 页面与流程验收矩阵

下面每行均须有可复现的输入、动作、结果和证据；passed 状态单独记录在实施证据，不反写规划时的核对范围。通用组件不内置这些业务规则，本地 controller 和消费者通过同一公开接口驱动它们。

| 界面/职责 | 必须可观察的行为 | 失败与恢复 |
| --- | --- | --- |
| 后台外壳 | A 的统一侧栏/顶部工具区；正确当前页，桌面折叠，移动打开/关闭；真实链接与消费路由适配 | Escape/遮罩/关闭恢复入口焦点，模态背景隔离；取消未保存离开不先换页或丢草稿 |
| 总览 | A 的指标、周期选择、真实样本趋势与活动；打开关联项目进入正确详情 | 数据加载/无数据/失败可表达；重试保持周期；图表尺寸明确、主题色更新，提供文本读数 |
| 项目列表 | B 的操作优先布局；全量样本搜索→筛选→排序→分页；稳定 id，当前页选择，关联详情 | 初次加载/更新中/失败/重试，无记录与无匹配结果分开；改查询/翻页清选择，旧查询结果不覆盖新结果 |
| 项目详情 | 独立页面；修改、dirty、校验、显式保存/取消；成功更新已保存值 | 失败保留草稿，字段错误可定位，重试成功；阻止重复提交；晚到结果不写到另一个项目；离开可继续编辑/放弃 |
| 成员 | 清单、邀请表单、角色/状态与消费者提供的可用动作；本地邀请有完成反馈 | 错误/提交中/不可用动作可辨；失败保留输入并可重试；模态焦点正确，不在通用 Table 写死领域权限 |
| 账单 | 当前方案、用量、方案选择、账单记录及本地结果；金额/币种/周期由数据显式给出 | pending/error/disabled 表达与重试；年总额与折算月价不混用，保留历史 annualPrice 语义；不执行真实支付 |
| 设置 | 复用 WorkbenchSettingsPage 的工作区信息、偏好与通知，通用主题外观；修改/保存/取消 | 失败保留输入，成功同步已保存值；未保存离开处理与详情一致，不为此复制第二份设置页 |
| 登录 | 表单、字段错误、提交中、本地成功结果；导航到注册/找回密码 | 失败保留适当输入和重试，敏感输入不进 URL/日志；本地完成不暗示真实会话已建立 |
| 注册 | 表单、字段错误、提交中、本地完成与登录入口 | 错误/重复提交防护与恢复；示例不承诺真实账号已创建 |
| 找回密码 | 邮箱表单、字段错误、提交中、本地完成与返回登录 | 失败可重试；完成明确是演示，不声称邮件已发出 |

跨页主流程：总览 → 查询/排序/翻页 → 当前页选择 → 打开指定项目 → 修改 → 保存失败 → 重试成功 → 返回列表恢复查询；另走未保存取消离开/放弃离开。Vite 与 Next 均执行，只有当前页面渲染，后台外壳保持稳定。

导航检查包括直接访问、刷新、浏览器前进/返回、关联 href 和适当的新标签行为；内嵌 Catalog 切屏不改详情 URL。未知页/样本 id 有明确未找到反馈。刷新后的查询/目标恢复是既定要求；未保存草稿不默认存浏览器或跨刷新恢复。浏览器返回的取消离开和关闭/刷新警告按消费包装的实际路径验证，不能只检查页面按钮。

账号界面不强制显示后台侧栏，页面入口和切换保留本地演示边界。运行示例不把 mock 请求错误变成未捕获浏览器异常。

## 主题、语言、响应式与可访问性

| 维度 | 必过样本 | 完成条件 |
| --- | --- | --- |
| 品牌 | Graphite + 一套真实且有区别的双模式 Theme Kit | 所有九类界面可使用两套品牌；第二套 token/身份实际登记并验证，原型蓝色不算已经支持 |
| 明暗 | 两品牌各自 light/dark；system 偏好另外检查初始及运行时变化 | 表面、文本、状态、表单、表格、图表与浮层完整更新；只有真实支持模式可以选择 |
| 语言 | 中文/英文固定文案、样本与消费文案适配 | 安装源码不依赖 UI Lab messages/next-intl；长英文与中文不挡住操作或状态 |
| 布局 | 九类界面的 1440px 桌面与 390px 窄屏；360/768px 对壳、列表、详情和账号关键布局补查 | 根页面不横向溢出，表格可在自身容器滚动，导航与主要操作仍可用 |
| 动效 | 普通与 reduce 的主要导航、弹窗、反馈和趋势显示 | reduce 保留状态/结果，取消不必要位移和延迟；SSR 首次结构稳定 |
| 键盘与焦点 | 全流程无鼠标；Tab/Shift+Tab、Escape、表单提交、分页/选择、开关与链接 | 可访问名称、当前页与错误说明准确；模态初始/限制/恢复、背景隔离、窄屏入口恢复实测 |
| 首帧/偏好 | Next 生产 SSR；两品牌/模式、系统偏好、记忆偏好、无效偏好、存储不可用 | 首帧与解析偏好一致，hydration 无可恢复错误；存储失败仍能会话切换；单模式 kit 不伪装双模式 |
| 状态保留 | 存在查询/页码/选择/dirty/保存中时切品牌与模式 | 不重挂载当前页面，不改变输入与提交目标；页面状态不归主题 provider 管理 |
| portal | Drawer、邀请及离开确认，在两品牌和两模式检查 | 浮层继承当前后台主题与覆盖；不影响外部 Catalog 偏好 |

生产全屏预览与 Next/Vite 消费者分别注明实际覆盖。基础展示矩阵至少覆盖九页×中英×两品牌×明暗×桌面/窄屏；错误、焦点、reduce 和首帧按上表关键流程补测，不重复每种无关组合的同一操作。精确场景集合在实施时冻结为清单，并核对预期/实际执行项，缺项不得汇总为通过。

Chromium/Chrome 是首轮自动化环境，记录真实版本。WebKit/Firefox、真实触摸设备和系统输入法若未实际验证，写清边界；不把一个浏览器的工程结果扩大成所有浏览器支持。色彩/状态不能只靠颜色传达；自动可访问性检查不能代替焦点与键盘操作或用户视觉判断。

## 分发、独立用法与消费者

每个新增安装身份，以及因共享 import/API 变化受影响的既有身份，都需按它自己的安装图校验；最终身份数以 registry targets 清单为准。不得通过“先把整站所有东西装完”掩盖某个独立页面遗漏 helper。

1. 窄图隔离用法：仅复制该入口 installationFiles 及登记用法，零参数 Consumer 严格类型、Bun SSR、浏览器打包、hydration；新增 sourceFiles/extraFiles 归属正确，示例 imports 不借未安装资产。
2. 真安装消费者：在 Next/Vite 的干净 React package 真实 shadcn 安装对应身份，typecheck/build/run。允许复用基础依赖缓存，不复用另一资产已经装好的源码。整站再执行完整组合主流程。
3. 手动复制：核对手动说明与 shadcn 来自相同 graph，至少在一个无 shadcn 自动安装的干净 Vite 包按说明复制完整整站并构建运行；不只检查文档列出的入口文件。
4. 既有消费者保留：有自定义变量/覆盖/源码的项目采用保留与补缺路径；证明安装组件不重写用户主题，显式选主题替换只改约定基线，用户拥有的覆盖仍有效。
5. 分发与机器接口：Catalog/registry/raw/独立 usage 对同一真实实现，缺真实引用停止快照；单页不强带无引用的图表库，无 UI Lab 站点 provider/Next/next-intl 依赖。
6. CLI 来源/锁定：准确显示来源和安装命令；有装配 config 时验证 add/compose 保留已存在 Lock 基准，显式 lock 才重建，缺 helper 失败/恢复，以及显式 source 失败无写入。若该轮未改 CLI 源码，复用现有回归并补新资产数据场景，不创建第二套审计工具。

Audit 只证明当前确定性规则，不能证明所有 API、CSS、外部包、业务、视觉或工程启动；这些由相应消费检查提供证据。

## 复用现有验证入口

以下是实施后的命令顺序与影响条件，本轮没有执行这些验收。实际定义已核对根 package.json 与脚本；不新增虚构测试命令。

| 阶段 | 现有入口 | 必要扩展/限制 |
| --- | --- | --- |
| 资产与共享 API | `bun run check:usage -- <真实用法 key>`；按影响加 `--browser` | key 从实际登记取得；当前浏览器脚本只覆盖桌面普通/390px reduce 的 Graphite 环境，需要补上表新主题与流程 |
| 登记/源码定稿 | `bun run cli:snapshot` | 刷新 sourceVersion 与快照；最终提交需包含快照，刷新不等于 npm 发布 |
| 根门禁 | `bun run check`、`bun run test` | check 包含 typecheck/lint/registry/catalog/architecture/snapshot/skills；必要行为回归按风险补，不写镜像实现的测试 |
| CLI 变更 | `bun run check:cli` | 只有 CLI 源码变化时另跑；源码命令先核对 `bun cli/src/index.ts --help` |
| Token 安装 | `bun run check:system-tokens` | 扩展新载荷的补缺、保留、显式替换与品牌作用域样本 |
| 生产站点 | 停同工作区 dev → `bun run build` → `bun run start` → `bun run check:catalog-site` | dev/build 共用 .next，不并行；新增双语详情/全屏深链/场景，不能沿用固定历史120场景当作新范围 |
| 独立消费者 | `bun run benchmark:catalog-assets -- next-app vite-app` | 脚本支持位置 Profile 参数；当前 assets/Graphite/浏览器流程硬编码旧样本，先扩展新身份、独立图与新流程再运行 |
| Modal/Drawer 共享变更 | `bun run check:modal-consumer` | 按实际影响补跨主题/portal/嵌套Escape与恢复场景；不是只要求现有命令再次绿灯 |

当前 benchmark 会把消费者实际解析的 package.json/lock 写回独立 fixture，实施中应审查这些任务内变化。benchmarks/runs/* 使用自己的工具链，不纳入根 TypeScript/Biome 扫描。历史168用法/336 hydration、36复制用法和三Profile结果属于原场景，不能充当新模板的结果。

## 实施顺序与每阶段可审查成果

| 阶段 | 工作与具体结果 | 阶段检查 |
| --- | --- | --- |
| 1 基础契约 | 定稿新增 props/内容/状态接口；兼容补齐 Table、Sidebar、BillingPlanGrid、Drawer/Modal、设置及 Stats；共享页码与必要 token/主题载荷 | 旧默认/身份不变；受影响窄用法通过；第二套真实主题和作用域接口成为可消费源码 |
| 2 核心纵向流程 | DashboardShell + 项目列表/详情 + 本地 controller，A 外壳/B 列表；查询→详情→编辑→失败/重试→返回 | 两模式可交互，导航/草稿/选择/焦点正确；在 Next/Vite 先跑通这一条真实流程 |
| 3 页面补齐 | 总览/Recharts 趋势、成员、账单、设置适配；三类账号 UI | 九类界面全部可触发自身状态，主题/中英文/窄屏符合矩阵，无仅画外观的占位流程 |
| 4 整站与发现 | 同一 ProjectWorkspaceSite 引用独立页面；真实登记/独立用法/预览/详情关联/用途/全屏路由 | provider-free 复制用法与安装闭包一致；正式预览不含原型捷径 |
| 5 完整交付验证 | 扩展实际消费者和站点场景，刷新快照，执行适用门禁，记录失败/修复/复测 | 根、分发、独立安装、生产运行和上表流程均有证据；正式视觉另外呈给用户评估 |

阶段成果可以分批审查，整站交付完成仍要求九类界面及所有必过路径；不把只完成壳/列表/详情称为首版完整模板。具体 prop 名、样本字段、精确子路径与源码 helper 共置是实施细化，不新增万能配置/服务框架；出现改变已确认职责或用户行为的实质取舍时才提出新决定。

成员角色/可用动作、账单币种金额/周期、字段校验由页面 props/示例数据明确；不扩大到组织权限、安全管理、真实支付或账号服务。需要的 mock 成功/失败确定且可重复，迟到异步结果、重复提交和错误恢复有实际语义检查。
