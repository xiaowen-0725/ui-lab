## 目标与已有确认

以客户项目协作工作区串联一个可交互的前端后台。用户已确认组件、区块、页面、外壳与整站的可组合方向；短期页面为总览、项目列表、项目详情、成员、账单、设置和登录/注册/找回密码入口。示例以本地数据和动作演示，消费者适配业务。全栈服务、工程生成器和部署不在本轮范围。

每个页面独立安装和整站使用必须引用同一份真实实现。复用票已确定资产职责与名字候选，目录票确定定位与登记，具体 props 在实现前收敛；以下名字不预先发布安装身份。

## 目录与登记边界

```text
components/
  motion/、agents/                已登记组件与区块；保持公开路径
  sections/                      已有页面区段；只复用职责相符的实现
  pages/                         后台六类页面与三类账号界面
  site-shells/                   后台外壳、引用独立页面的整站入口
  examples/
    pages/                       各页面零参数、本地可交互用法
    sites/                       连贯整站用法与本地演示 controller
  previews/
    pages/、sites/               UI Lab 站点包装与展示控制

lib/
  pages.ts                       页面登记事实
  sites.ts                       整站登记事实及页面/外壳引用
  registry.ts                    安装身份投影
  theme-kits/                    共享视觉 token
```

首版采用职责目录的扁平入口，详细决定见[目录与登记 resolution](https://github.com/xiaowen-0725/ui-lab/issues/29#issuecomment-6035259967)。需要共享的纯 helper 依据真实使用点共置或抽出；不先建立通用 forms/store/services 目录，不批量迁移历史 motion/agents 源码。系列子目录保留为未来真实共置需求出现时的演进备选，详见[架构对比](2026-10-07-site-architecture-options.md)。

当前源码证据：

- [registry](../../lib/registry.ts) 的 PAGES/SITES 投影按 componentSlug 推导扁平入口路径；子目录方案会涉及定位契约变更。
- [SiteDefinition](../../lib/sites.ts) 的 componentSlug、shellComponent、recommendedSystem 和 pagePath 写死了 Agent 工作台；增加后台时必须允许第二项实际登记，同时保留旧项与身份。
- `assetRole` 和 source family 继续沿用 [ADR 0002](../../docs/adr/0002-catalog-roles-and-install-identities.md)。页面/壳/整站的安装闭包由实际 import 图决定，不能复制预览文件当作安装实现。
- 用途发现沿用整站入口及 SITES 投影；具体字段/API 在实施中收敛，不新增第二份模板清单来维护同一事实。

成员动作、账单金额单位和字段校验细节尚未锁定；不要把本表的界面行为描述成这些业务规则已经实现。列表选择已限定当前页，翻页或改查询清空；契约详见上方 resolution。

## 外壳、整站和消费者的接口候选

| 对象 | 建议负责 | 明确的消费适配入口 |
| --- | --- | --- |
| 后台外壳 | brand/header/navigation/content/footer 区域；桌面折叠与移动开关；导航可访问行为 | 导航条目、activeId、href 或链接渲染适配；不读取 Next pathname |
| 独立页面 | 内容、业务数据展示、查询/编辑状态及显式动作 | locale/content/data/value/state 与 callbacks；不发业务请求 |
| 整站组合 | 引用独立外壳与页面，按当前页面渲染并传递对应页面 props | 当前页面/详情目标、导航适配及页面数据；不维护另一个业务数据库 |
| 本地示例 controller | 样本记录、查询、保存/错误恢复与本地状态 | 调用相同公开 props/回调；演示数据不成为页面内固定数据 |
| 消费者路由包装 | 路由映射、深链、参数、返回/刷新和离开策略 | 将 URL 等消费者状态投影为纯 React props；主题 provider 在工程包装中配置 |
| UI Lab 预览 | 双语站点文案、展示尺寸与演示状态控制 | 包装同一真实页面/整站；next-intl 不进入安装闭包 |

具体 prop 名字、导航条目 shape 和页面标识还不是公开 API。简单 slots 不升级成万能 schema；静态区域不为统一接口额外增加回调。

### 导航与页面生命周期

用户已确认完整前端示例支持独立页面地址、详情深链、刷新和浏览器返回；内嵌 Catalog 预览保留在单一预览地址切屏的能力。详细职责、生命周期与焦点边界见[导航 resolution](https://github.com/xiaowen-0725/ui-lab/issues/30#issuecomment-6034315845)；具体 URL 和公开字段名仍待实现收敛。

建议导航使用真实 href，允许消费者提供 Router Link 适配；原生链接的打开新标签页等行为应保留。纯 React 内嵌用法通过当前页面和动作回调驱动，不能强制安装 Next/TanStack Router。URL 路径与参数由示例/消费工程定义，不成为页面源码的业务约束。

建议只渲染当前页面；稳定后台外壳可以跨页保留。页面按需加载属于消费者包装。现有 [AgentWorkbenchSite](../../components/site-shells/agent-workbench-site.tsx) 将三个页面全部挂载并 hidden 的策略用于其草稿体验，不应默认推广到所有后台页面。

### 查询、草稿和焦点

- 列表查询由消费者/controller 持有。本地示例先对全部样本执行搜索、筛选和排序，再分页；真实 API 的参数映射留消费者。完整示例由路由包装记录可分享查询与页码，从详情返回恢复；内嵌预览可由父状态持有。
- 详情编辑已采用显式保存起点。消费者获知 dirty/提交状态，先决定离开再更新当前页面；取消离开应保持草稿与当前页。跨页或刷新后的草稿存储另行讨论，不能靠所有页面永远挂载隐式实现。
- 导航选择成功后才关闭移动导航并聚焦新内容；取消导航时保留原内容和可用焦点。关闭移动菜单应恢复合理入口焦点。具体焦点和背景隔离由实际采用的导航/模态实现验证。
- 切主题不改变当前页面身份或给整站换 key。查询、草稿与保存状态不由主题 provider 管理。

已确认的导航规格仍需在真实框架消费者中验证浏览器返回/离开拦截及焦点恢复；回调存在不证明所有导航方式已经运行通过。查询与编辑的具体公开字段、URL 编码以及异步适配在实现中收敛。

## 列表与编辑的数据契约

以下是已确认契约在本草案中的接口推导，以票中 resolution 为准；不是已完成的接口实现，也不新增通用数据框架。

| 事项 | 首版契约 | 适配边界 |
| --- | --- | --- |
| 查询状态 | 搜索、筛选、排序、页码、每页数量由示例/消费者控制；改变搜索/筛选/排序/每页数量时回到第一页 | 页面表达变化，controller 执行查询；不改消费者原有 API 参数 |
| 本地查询 | 全部样本 → 搜索/筛选 → 排序 → 页码切片；同一查询产生 rows 与 total | 通用 Table 不负责请求，不把当前页排序标作全局排序 |
| 查询恢复 | 完整示例将可分享的查询条件和页码映射 URL；从详情返回按原查询恢复 | 内嵌示例可由父状态持有；查询内容限非敏感示例字段，消费者决定自身映射 |
| 结果状态 | 正常结果、首次加载、更新中、查询失败分别表达；无记录与无筛选结果区分 | 重试保留原查询；更新中的交互策略在具体页面实现核验 |
| 行身份 | 真实稳定业务 id，排序/查询后不改身份 | 不使用数组 index 代表业务记录，不写入通用表格领域权限 |
| 选择范围 | 首版仅选择当前页，翻页或改查询清空；用户本轮已接受 | 保留 Table 的受控 ids 接口；页面/controller 实施首版规则，不改变历史 Table 默认行为 |
| 批量结果 | 如页面需要批量动作，明确已选数量、执行中、成功/失败与恢复入口 | 首版不提供跨页全选，不推导“全部查询结果已选中” |
| 异步结果 | 查询与记录目标变化后，不让旧结果覆盖新页面；取消/忽略由 controller 处理 | UI 接收最新状态，不内置 fetch 或固定请求库 |

现有 [useColumnSort](../../components/motion/table/use-column-sort.ts) 在 sort 受控时仍对传入 rows 排序，没有手动排序模式。实现全局查询契约需要明确扩展方案；不能只增加 onSortChange 就认定服务端排序已支持。是否扩展同一 Table 的接口/变体由复用票决定，首版不默认换用另一套表格库。

详情编辑建议采用：已加载数据初始化当前编辑会话 → 修改形成 draft/dirty → 消费者校验及提交 → 成功后同步已保存值，或失败时保留草稿/字段错误供修正重试。取消编辑恢复本会话已保存值；保存中状态与导航离开配合，不用输入一次就保存一次的通用单元格接口替代整页提交。

字段规则、保存结果、权限/冲突反馈由消费者提供，页面只表达错误和可用动作。首版不默认乐观提交、不自动持久化草稿到浏览器存储；跨页/刷新草稿恢复需要另行定义。重复提交防护与晚到结果的目标校验由 controller 承接并按实际示例验证。

建议在本地示例中能明确触发保存失败、修正后重试和未保存取消离开，使用同一公开接口，不仅在 preview 中安排这些状态。

## 主题契约

用户本轮已确认首版默认体验：模板内提供品牌与 light/dark/system 切换，记住本机偏好，切换保留页面/查询/草稿；只允许 kit 实际支持的模式。具体技术职责以主题票 resolution 为准；先完成 graphite 和第二套真实双模式品牌的兼容验证，再扩大主题范围。本轮视觉选择确定布局组合，第二套真实双模式 kit 的具体 token 与安装身份仍需在实现中形成候选并验证；原型蓝色不代表已有兼容 Theme Kit。

| 事项 | 首版契约及接口推导 | 实施边界 |
| --- | --- | --- |
| 品牌与模式 | Theme Kit 身份与 light/dark/system 偏好分别控制；system 解析为 light 或 dark | system 是消费者偏好，不是 ThemeKit.modes 新增的第三套 token |
| 基线 | 先用实际双模式 graphite 检验所有页面，再确定一套有区别且双模式完整的品牌候选验证替换 | 第二套的 token 与实际支持范围在实现候选中验证；不宣称所有 kit 已兼容 |
| 主题覆盖 | 语义色、表面/边框、状态色、图表色，以及 kit 自身字体/圆角/阴影等静态值 | 具体字体资源需消费工程加载；换 token 不证明图表/Canvas/第三方 UI 都更新 |
| 安装 | 显式选择主题采用已有替换语义；后续安装组件沿用补缺规则 | 不覆盖消费者业务样式或把完整主题复制进每个资产 |
| 预览 | 同一真实页面能以支持的品牌/模式预览，覆盖正常/错误/编辑状态 | 预览切换不等同消费者 runtime 已支持 |
| 运行时 | 完整示例默认提供品牌与明暗切换，消费者可控制或隐藏入口；切换不重建页面、丢失草稿或查询 | 保留选择与提交中状态；品牌作用域、portal 继承和初始化需消费验证 |
| 用户偏好 | 同一应用、本机浏览器记忆；首次 graphite + system，失效选择回退有效默认；存储不可用仍可会话切换 | 消费包装负责预绘制 CSS 与稳定 hydration；账户/组织同步由消费者接入 |
| 单模式 kit | 按真实 modes 表达能力；只开放原生模式，不提供不支持模式或 system | 历史 fallback CSS 不等于双模式；首版后台运行时优先限于验证过的双模式 kit |
| 用户定制 | kit 基线与用户覆盖区分；切换/升级保留用户拥有的源码和覆盖 | 精确 CSS 作用域/优先级方案在实现前收敛并验证 |

本地事实依据：[ThemeKit 类型](../../lib/theme-kits/types.ts)、[合成](../../lib/theme-kits/compose.ts)和[生成/主题研究](2026-10-07-project-generation-themes.md)。当前 kit 载荷输出使用 :root/.dark，多品牌原样拼接会竞争；支持运行时品牌选择需要作用域/初始化契约，尚未实现。

接口推导：消费根表达品牌与解析模式，从同一 kit 生成各品牌作用域 token；用户覆盖与生成基线分开，切换不重写覆盖。字体资源由消费工程加载，主题只改变 token，不加入任意布局编辑器。直接修改生成基线不等于可自动合并升级；准确选择器、API 和载荷分发在目录/安装票及实际实现中确定，保留已有单主题输出契约。

首版主题兼容建议至少覆盖表格、表单、账单、侧栏、弹窗、图表、空/错误状态及中英文窄屏文案。保留普通/减少动效和 SSR 场景；品牌数量不是通过标准，未运行验证的 kit 不列为已支持。

## 已有资产的复用与补齐

依据[已完成资产审计](2026-10-07-site-template-reuse.md)及[复用补齐决定](https://github.com/xiaowen-0725/ui-lab/issues/35#issuecomment-6035093678)。下表记录职责推导，详细决定以票中 resolution 为准，不是新的运行验收结论。

| 能力 | 采用方向 | 进入实现前要补齐或确认 |
| --- | --- | --- |
| 列表展示 | 已有 Table 与真实变体 source family | 分页/手动排序契约；稳定 row id；错误/重试与键盘操作。当前本地排序不能冒充服务端全局排序 |
| 表单与反馈 | 已有 Input、Checkbox、Switch、StatefulButton | 字段错误、dirty、saving、失败恢复等页面契约；与表单库适配是否确有必要 |
| 导航 | 已有 CollapsibleSidebar 的结构与接口 | 语义 token、href/链接适配、移动开关、折叠名称/焦点；新增壳不复制另一个通用侧栏 |
| 总览 | ActivityStats、职责吻合的区段 | 后台密度和窄屏；趋势图职责与基础实现另选，热图不替代折线图 |
| 设置 | 扩展同一 WorkbenchSettingsPage、分组/行控件及页面状态 helper | 首版保留工作区名称/偏好/通知，补通用 token 外观与保存事务；不扩展组织安全等业务范围、不新建重叠设置页 |
| 账单 | BillingPlanGrid 的方案数据与动作 | 固定暗色/紫色、中文文案、计价含义和 pending/error；记录列表是另一个组合职责 |
| 命令入口 | 现有 CommandPalette 留可选增强，不列首版必装 | 焦点限制/恢复、本地化等缺口另验收；首版检索由页面查询承接 |

扩展同一职责补现有实现或增加真实变体；新增职责再建资产。不得因为参考项目使用某库就自动装一套相同依赖。本文不发布一份平行的 approved 清单，运行和视觉结果仍分别记录。

### 主题与数据契约确认后的补齐方案

本节是复用补齐决定在草案中的接口推导。首版六类后台页中，五类新增，设置页扩展既有真实入口；另新增三类账号页。详细决定在上方链接中，具体定位待目录票。

| 处理方式 | 首版范围 | 兼容与职责依据 |
| --- | --- | --- |
| 直接组合已有能力 | Input、Checkbox、Switch、StatefulButton、Select、DropdownMenu、Drawer；按职责使用已有指标/状态内容 | 复用真实入口与 helper，不建立第二套基础控件；每个所选用法仍验证双语、键盘、SSR 与 reduce |
| 对同一 Table 增量扩展 | 增加消费方排序模式，显示排序状态但不对传入页重复排序；项目/成员页传稳定 id，外部组合查询栏、页码、错误与重试 | 本地排序保持历史默认；不在 Table 内增加请求、权限或跨页选择；首版不开放业务用户改列结构 |
| 对同一侧栏增加主题用法 | 可选语义 token 外观、href/Link 适配、折叠可访问名称和触摸/键盘可用动作；移动开关由新外壳组合 Drawer | 保留旧 id 回调、默认外观与公开身份；如单独展示主题变体，仍引用同一真实 source family |
| 对同一方案区块增加主题用法 | 可选语义外观、可传中英文固定文案、明确金额/计费周期展示、pending/error/disabled 反馈 | 不偷偷重解释历史 annualPrice；新展示接口明确年总额与折算月价。账单记录由页面组合，不复制方案区块 |
| 对同一设置页/控件增加后台用法 | WorkbenchSettingsPage 与 SettingsGroup/Row 补通用语义外观、错误/dirty/saving/取消/失败恢复及允许模式 | 保留旧页面身份、Workbench 默认和 wb token；后台语义用法不依赖 wb token。首版沿用三类偏好，不加入组织安全或密钥职责 |
| 复用模态基础 | 移动导航用 Drawer；邀请/离开确认使用已有 Modal 与 useModalDialog 的公共基础 | [Drawer](../../components/motion/drawer.tsx) 已引用 [Modal](../../components/ui/modal.tsx)，无需再手写焦点限制/背景隔离。Drawer 默认关闭名称及 Modal 的 body portal 主题继承需补可适配入口并实测；它们存在不等于本轮已验收 |
| 新增实际组合职责 | 五类后台页面、三类账号页面、共用后台外壳及引用页面的整站；各自配独立用法 | 设置引用旧真实页面。分发页面接值/状态/动作，示例 controller 承接本地查询和保存；旧条目不迁移，账号页不强制显示后台侧栏 |
| 新增页码与趋势职责 | 共享页码控件；趋势图使用 Recharts，参考 shadcn 官方 Chart 的组合方式，适配本项目 token、双语读数与文本数据替代 | 页码逻辑不在每页复制；趋势不另造坐标/tooltip 引擎。依赖版本与安装成本验证，不照搬上游完整封装 |
| 暂不作为首版必装 | 全局命令面板、升级权益锁定、表格列编辑/拖拽、完整图表编辑器 | 不影响已确认的查询/编辑/邀请/账单演示流程；需要时单独补齐已有能力。首版检索先由页面查询承接 |

趋势候选第一方核对（2026-10-07）：[shadcn Chart](https://ui.shadcn.com/docs/components/radix/chart) 当前采用 Recharts v3 并强调组合，响应式容器需要明确高度；其示例使用 accessibilityLayer。候选成本是新增图表依赖与安装闭包验证，不能用官网示例代替本仓库运行证据。基础 Table/事务表单首版没有已证明必须切换到 TanStack Table 或引入表单框架的需求。

[Recharts 官方仓库](https://github.com/recharts/recharts) 安装说明要求 react-is 与已安装 React 版本匹配；实施时在真实安装图核对解析版本、响应式尺寸、hydration 与键盘读数。它是本轮新增候选，当前根依赖尚未加入，不报告安装成功或包体积结论。

新增职责的名字已在复用票形成候选：WorkspaceOverviewPage、ProjectListPage、ProjectDetailPage、WorkspaceMembersPage、WorkspaceBillingPage、AccountSignInPage、AccountSignUpPage、PasswordRecoveryPage、DashboardShell、ProjectWorkspaceSite、PagePagination、MetricTrendChart。目录票据此确定入口，不照搬上游品牌/专属名。参考界面模式保留来源，若移植源码则保留实际 revision/作者/许可。已有 Drawer/Modal 为补读的源码事实，历史审计范围保持原记录。

## 发现、预览与安装路径

## 进入实施前的检查顺序

1. 明确外壳/路由、列表/编辑和主题契约，完成复用/新增资产取舍。
2. 据实际资产确定源码定位和登记变化，完成一个可供用户判断的明暗与移动视觉候选。
3. 明确发现/独立安装入口和真实消费者验收范围，再整理实施清单。

后续验证至少覆盖每个独立安装图、连贯后台流程、加载/空/错误/保存恢复、明暗、移动导航、键盘、SSR 与减少动效；消费者运行通过和用户视觉批准分别记录。本文没有新增入口、运行测试、提交或发布。
